# 설계 요약과 결정 사항

전체 설계서: claude.ai 문서 「국악 특화 웹 작곡 프로그램 설계서」(2026-11-23). 여기에는 개발하면서 정한 것과 설계서의 요점만 적는다.

## 결정한 것

| 날짜 | 결정 | 이유 |
|---|---|---|
| 2026-11-24 | 프로그램 이름 **ScoreWorks Studio**, 저장소 commst/scoreworks_studio (기본 브랜치 dev) | 사용자가 만든 저장소 이름 |
| 2026-11-24 | ScoreWorks와 **따로 두고 공통 모듈을 복사해 공유**(tools/sync-shared.mjs) | 단원이 쓰는 ScoreWorks를 건드리지 않고, 해석기·재생은 한 곳(ScoreWorks)에서만 고침 |
| 2026-11-24 | 오선 조판 **Verovio** (OSMD/VexFlow와 비교) | 월광 총보(20줄 193마디) 2.9초 vs 5.9초, 총보 묶음 괄호·간격이 깔끔, 음마다 ID·편집 명령·재생 시각표가 있어 1단계(눌러서 고치기·따라가기)에 유리. 크기는 압축 약 2.4MB(OSMD 0.4MB). 여러 마디 쉼표는 옵션을 맞춰야 함 |
| 2026-11-24 | 화면 그리기도 **.swc → MusicXML → Verovio** | 보이는 것과 내보낸 MusicXML이 늘 같음(ScoreWorks에서 MusicXML 내보내기가 가장 중요했던 점) |
| 2026-11-24 | Vite + TypeScript, 화면은 프레임워크 없이(DOM) | 작은 시작, 빌드 대상 ES2020 |
| 2026-11-24 | 실제 악보는 공개 저장소에 넣지 않음 | 저작권 — 시험은 비공개 샘플 저장소의 파일로 |

## 아직 정하지 않은 것 (설계서 7장)

- 정간보를 3단계로 둘지, 더 앞으로 당길지
- 국악 기호의 기본 모양, 장구 기본 표기(오선 / 합장단 기호)
- 공개 범위(늘봄 단원용 / 일반 공개)와 소스 라이선스

## 개발 단계 (설계서 6장)

| 단계 | 내용 | 완료 기준 | 상태 |
|---|---|---|---|
| 0 | 조판 라이브러리 비교, 공통 모듈 분리, .swc 형식 | 라이브러리·이름·형식 결정 | **끝 (11-24)** |
| 1 | 불러와 보기·편집·재생 — PDF·MusicXML 불러오기, 음 입력·수정·되돌리기, 국악기 녹음 재생, 편성 템플릿, 자동·GitHub 저장, MusicXML 내보내기 | 샘플 5곡을 불러와 고친 뒤 피날레에서 같은 악보로 열림 | 진행 중 — MusicXML 불러와 보기·재생 됨(11-24) |
| 2 | 국악 기능·새 악보 — 마법사, 장단 반주, 주법 기호, 음역·조율 검사, 파트보 | 새 곡을 처음부터 만들어 총보·파트보 PDF로 합주 | |
| 3 | 정간보·고급 조판 | 정간보 샘플 재현, 오선보↔정간보 왕복 | |
